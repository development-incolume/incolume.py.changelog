    0. Premissa#

    O CHANGELOG é saída do próprio incolume.py.changelog, gerado a partir das anotações das tags (git tag -n). Ele nunca é editado à mão e não é traduzido arquivo a arquivo. Toda correção de conteúdo do CHANGELOG passa por corrigir o gerador (ou a anotação da tag) e regerar com uv run task changelog.

    Consequência verificada: o docs/about/CHANGELOG commitado na 1.5.0 saiu com mojibake (repositÃ³rio, SerÃ¡) porque a leitura de subprocess.getoutput('git tag -n') usa o locale da máquina. Rodando a ferramenta neste ambiente, a saída é UTF-8 correta. O defeito, portanto, é do caminho de leitura do gerador — não do arquivo.

    • As traduções existentes (de/en/es/fr/it) não tiveram revisão linguística; a divergência de extensão já encontrada (COVENTIONAL_COMMITS.en 84 × COVENTIONAL_COMMITS 31 linhas) indica conteúdo divergente.

    4. Proposta de melhoria#

    1. Uma fonte de verdade por documento, pt-BR como default e demais idiomas como tradução — sem fallback silencioso para conteúdo específico do projeto.
    2. Separar referência genérica (semver, keep-a-changelog, conventional, zenpy) de guia do projeto (development, installation, usage, api), que tem de ser 100% específico.
    3. Acionável: todo comando e versão precisa bater com pyproject.toml, tox.toml e os workflows reais.
    4. Automatizar: CI de docs que instala o grupo doc e valida links e encoding antes do deploy.
    5. Navegação completa: todo .md de docs/ ou está no nav ou é removido.
    6. CHANGELOG é gerado: nenhuma tarefa prevê edição ou tradução manual.
    7. Revisão textual em todos os idiomas: ortografia, gramática, coerência e padronização de termos, com glossário de termos do projeto, aplicada a cada documento antes de aceito.
