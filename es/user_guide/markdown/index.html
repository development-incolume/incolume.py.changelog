    Markdown - Sintaxis básica#

    basado en https://www.markdownguide.org/basic-syntax/

    Visión general#

    Casi todas las aplicaciones de Markdown admiten la sintaxis básica descrita en el documento de diseño original de Markdown. Existen pequeñas variaciones y discrepancias entre los procesadores de Markdown; se anotan en el texto siempre que es posible.

    Títulos#

    Para crear un título, añade signos de número (#) delante de una palabra o frase. La cantidad de signos de número que uses debe corresponder al nivel del título. Por ejemplo, para crear un título de nivel tres (<h3>), usa tres signos de número (por ejemplo, ### My Header).

    Marcado HTML Salida renderizada
    # Heading level 1 <h1>Heading level 1</h1>

    Heading level 1
    # Heading level 2 <h2>Heading level 2</h2>

    Heading level 1
    # Heading level 3 <h3>Heading level 3</h3>

    Heading level 3
    # Heading level 4 <h4>Heading level 4</h4>

    Heading level 4
    # Heading level 5 <h5>Heading level 5</h5>
    Heading level 5
    # Heading level 6 <h6>Heading level 6</h6>
    Heading level 6

    Sintaxis alternativa#

    Como alternativa, en la línea debajo del texto, añade cualquier número de caracteres == para un título de nivel 1 o caracteres -- para un título de nivel 2.

    Marcado HTML Salida renderizada
    Heading level 1
    ===============    		 <h1>Heading level 1</h1>

    Heading level 1
    Heading level 2
    ---------------    		 <h2>Heading level 2</h2>

    Heading level 2

    Encabezados: mejores prácticas#

    Las aplicaciones de Markdown no se ponen de acuerdo sobre cómo tratar la falta de espacio entre los signos de número (#) y el nombre del título. Por compatibilidad, coloca siempre un espacio entre los signos de número y el nombre del título.

    ✅  Haz esto ❌  No hagas esto
    # Here's a Heading #Here's a Heading

    También debes colocar líneas en blanco antes y después de un título por compatibilidad.

    ✅ Haz así ❌ No así
    Try to put a blank line before...

    # Heading

    ...and after a heading.    		 Without blank lines, this might not look right.
    # Heading
    Don't do this!

    Párrafos#

    Para crear párrafos, usa una línea en blanco para separar una o más líneas de texto.

    Markdown HTML Salida renderizada
    Paragrafo1.

    Paragrafo2.    		 <p>Paragrafo1.</p><p>Paragrafo2.</p> Paragrafo1.
    Paragrafo2.

    Mejores prácticas de párrafo#

    A menos que el párrafo esté en una lista, no sangres los párrafos con espacios ni tabulaciones.

    ℹ Nota: Si necesitas sangrar párrafos en la salida, consulta la sección sobre cómo sangrar (tabulación).

    ✅  Haz esto ❌  No hagas esto
    No coloques tabulaciones ni espacios antes de los párrafos. Esto puede provocar problemas de formato inesperados.
    Mantén las líneas alineadas a la izquierda así. No añadas tabulaciones ni espacios antes de los párrafos.

    Saltos de línea#

    Para crear un salto de línea o una nueva línea (<br>), termina la línea con dos o más espacios y pulsa Enter.

    Marcado HTML Salida renderizada
    Esta es la primera línea.

    Esta es la primera línea.

    		 Esta es la primera línea.
    Y esta es la segunda línea. Y esta es la segunda línea.

    		 Y esta es la segunda línea.

    Prácticas recomendadas para saltos de línea#

    Puedes usar dos o más espacios (lo que se denomina habitualmente "espacios en blanco finales") para los saltos de línea en casi todas las aplicaciones de Markdown, pero es algo controvertido. Cuesta ver los espacios en blanco al final en un editor, y muchas personas colocan dos espacios de forma accidental o intencionada después de cada frase. Por ese motivo, quizá prefieras usar otra cosa distinta de los espacios en blanco finales para los saltos de línea. Si tu aplicación de Markdown admite HTML, puedes usar la etiqueta HTML <br>. Você pode usar dois ou mais espaços (comumente chamados de "espaços em branco finais") para quebras de linha em quase todos os aplicativos Markdown, mas isso é controverso. É difícil ver espaços em branco no final de um editor, e muitas pessoas acidentalmente ou intencionalmente colocam dois espaços após cada frase. Por esse motivo, você pode querer usar algo diferente de espaços em branco à direita para quebras de linha. Se o seu aplicativo Markdown suportar HTML, você poderá usar a <br> tag HTML. Por compatibilidad, usa el espacio en blanco final o la etiqueta HTML <br> al final de la línea. Para compatibilidade, use o espaço em branco final ou a <br> tag HTML no final da linha. Hay otras dos opciones que no recomiendo usar. CommonMark y algunos otros lenguajes de marcado ligeros permiten escribir una barra invertida ( \ ) al final de la línea, pero no todas las aplicaciones de Markdown lo admiten, por lo que no es una buena opción en términos de compatibilidad. Y al menos algunos lenguajes de marcado ligeros no necesitan nada al final de la línea: basta con pulsar Enter y crearán un salto de línea. Existem duas outras opções que não recomendo usar. CommonMark e algumas outras linguagens de marcação leves permitem digitar uma barra invertida ( \ ) no final da linha, mas nem todos os aplicativos Markdown suportam isso, portanto, não é uma ótima opção do ponto de vista de compatibilidade. E pelo menos algumas linguagens de marcação leves não exigem nada no final da linha - basta digitar return e elas criarão uma quebra de linha.

    ✅  Haz esto ❌  No hagas esto
    Primera línea con dos espacios al final. Primera línea con una barra invertida al final.\
    Y la siguiente línea. Y la siguiente línea.
    Primera línea con la etiqueta HTML al final.
    		 Primera línea sin nada al final.
    Y la siguiente línea. Y la siguiente línea.

    Énfasis#

    Puedes añadir énfasis poniendo el texto en negrita o cursiva.

    Negrita#

    Para el texto en negrita, añade dos asteriscos o guiones bajos antes y después de una palabra o frase. Para poner en negrita la parte central de una palabra y dar énfasis, añade dos asteriscos sin espacios alrededor de las letras.

    Marcado HTML Salida renderizada
    Me encanta **texto en negrita**. Me encanta texto en negrita. Me encanta texto en negrita .
    Me encanta __texto en negrita__. Me encanta texto en negrita. Me encanta texto en negrita .
    El amor **es** en negrita El amores en negrita El amor es en negrita

    Mejores prácticas en negrita#

    Las aplicaciones de Markdown no se ponen de acuerdo sobre cómo tratar los guiones bajos en medio de una palabra. Por compatibilidad, usa asteriscos para la negrita en medio de una palabra y dar énfasis.

    ✅  Haz esto ❌  No hagas esto
    El amor **es** en negrita El amor__es__ en negrita

    Cursiva#

    Para poner el texto en cursiva, añade un asterisco o un guion bajo antes y después de una palabra o frase. Para poner en cursiva la parte central de una palabra y dar énfasis, añade un asterisco sin espacios alrededor de las letras.

    Marcado HTML Salida renderizada
    El texto en cursiva es el *maullido del gato*. El texto en cursiva es el maullido del gato. El texto en cursiva es el maullido del gato .
    El texto en cursiva es el _maullido del gato_. El texto en cursiva es el maullido del gato. El texto en cursiva es el maullido del gato .
    Un *gato* maulla Un gato> maulla Un gato maulla

    Mejores prácticas en cursiva#

    Las aplicaciones de Markdown no se ponen de acuerdo sobre cómo tratar los guiones bajos en medio de una palabra. Por compatibilidad, usa asteriscos para la cursiva en medio de una palabra y dar énfasis.

    ✅  Haz esto ❌  No hagas esto
    Un *gato* maulla Un_gato_ maulla

    Negrita y cursiva#

    Para enfatizar el texto con negrita y cursiva a la vez, añade tres asteriscos o guiones bajos antes y después de una palabra o frase. Para poner negrita y cursiva en medio de una palabra y dar énfasis, añade tres asteriscos sin espacios alrededor de las letras.

    Marcado HTML Salida renderizada
    Este texto es ***realmente importante***. Este texto es <em><strong>realmente importante</strong></em>. Este texto es realmente importante.
    Este texto es ___realmente importante___. Este texto es <em><strong>realmente importante</strong></em>. Este texto es realmente importante.
    Este texto es __*realmente importante*__. Este texto es <em><strong>realmente importante</strong></em>. Este texto es realmente importante.
    Este texto es **_realmente importante**_. Este texto es <em><strong>realmente importante</strong></em>. Este texto es _realmente importante_.
    Este texto es realmente ***muy*** importante. Este texto es realmente <em><strong>muy importante</strong></em>. Este texto es realmente muy importante.

    ℹ Nota: el orden de las etiquetas em y strong puede invertirse según el procesador de Markdown que uses.

    Prácticas recomendadas para negrita y cursiva#

    Las aplicaciones de Markdown no se ponen de acuerdo sobre cómo tratar los guiones bajos en medio de una palabra. Por compatibilidad, usa asteriscos para negrita y cursiva en medio de una palabra y dar énfasis.

    ✅  Haz esto ❌  No hagas esto
    Este texto es realmente ***muy*** importante. Este texto es realmente___muy___importante.

    Citas en bloque#

    Para crear una cita en bloque, añade un > delante de un párrafo.

    > Dorothy followed her through many of the beautiful rooms in her castle.

    La salida renderizada queda así:

    Dorothy la siguió por muchas de las hermosas habitaciones de su castillo.

    Citas en bloque con varios párrafos#

    Las citas en bloque pueden contener varios párrafos. Añade un > en las líneas en blanco entre los párrafos.

    > Dorothy a seguiu por muitos dos belos quartos de seu castelo.

>

> A Bruxa ordenou-lhe que limpasse as panelas e as chaleiras, varresse o chão e mantivesse o fogo alimentado com lenha.

    La salida renderizada queda así:

    Dorothy la siguió por muchas de las hermosas habitaciones de su castillo.

    La Bruja le ordenó que limpiara las cacerolas y los calderos, barrera el suelo y mantuviera el fuego alimentado con leña.

    Citas anidadas#

    Las citas en bloque pueden anidarse. Añade un >> delante del párrafo que quieras anidar.

    > Dorothy a seguiu por muitos dos belos quartos de seu castelo.

>

>> A Bruxa ordenou-lhe que limpasse as panelas e as chaleiras, varresse o chão e mantivesse o fogo alimentado com lenha.

    La salida renderizada queda así:

    Dorothy la siguió por muchas de las hermosas habitaciones de su castillo.

    La Bruja le ordenó que limpiara las cacerolas y los calderos, barrera el suelo y mantuviera el fuego alimentado con leña.

    Citas en bloque con otros elementos#

    Las citas en bloque pueden contener otros elementos formatados en Markdown. No todos los elementos se pueden usar

    > #### Os resultados trimestrais parecem ótimos!

>

> - A receita estava fora do gráfico.

> - Os lucros foram maiores do que nunca.

>

> *Tudo* está indo conforme o **planejado** .

    La salida renderizada queda así:

    ¡Los resultados trimestrales parecen geniales!#

    • Los ingresos se salían de las gráficas.
    • Los beneficios fueron mayores que nunca.

    Todo va según lo planeado .

    Prácticas recomendadas para citas en bloque#

    Por compatibilidad, coloca líneas en blanco antes y después de las citas.

    ✅  Haz esto ❌  No hagas esto

    > Esto es una cita en bloque\
    > Esto es una cita en bloque ¡No hagas esto!\
    ...y después de una cita en bloque.

    Mejores prácticas de lista ordenada#

    CommonMark y algunos otros lenguajes de marcado ligeros permiten usar paréntesis ( )) como delimitador (por ejemplo, 1) First item), pero no todas las aplicaciones de Markdown lo admiten, por lo que no es una buena opción en términos de compatibilidad. Por compatibilidad, usa solo puntos.

    2. Second item 2) Second item

    Añadir elementos a las listas#

  <head>
    <title>Test</title>
  </head>

    3. Actualiza el título para que coincida con el nombre de tu sitio.

    Reglas horizontales#

    Para crear una regla horizontal, usa tres o más asteriscos ( *** ), guiones ( --- ) o guiones bajos ( ___ ) en una línea, solos.

    ***

    Enlaces#

    Para crear un enlace, pon el texto del enlace entre corchetes (por ejemplo, [Duck Duck Go]) y síguelo inmediatamente con la URL entre paréntesis (por ejemplo, (https://duckduckgo.com)).

    My favorite search engine is [Duck Duck Go](https://duckduckgo.com).

    La salida renderizada queda así:

    Mi buscador favorito es Duck Duck Go.

    ℹ Nota: Para enlazar a un elemento de la misma página, consulta enlazar a IDs de encabezado . Para crear un enlace que se abra en una pestaña o ventana nueva, consulta la sección sobre destinos de enlace.

    Añadir títulos#

    Opcionalmente, puedes añadir un título a un enlace. Aparecerá como un consejo cuando el usuario pase el ratón por encima del enlace. Para añadir un título, colócalo entre comillas después de la URL.

    My favorite search engine is [Duck Duck Go](https://duckduckgo.com "The best search engine for privacy").

    La salida renderizada queda así: Meu mecanismo de pesquisa favorito é Duck Duck Go. Mi buscador favorito es Duck Duck Go.

    Enlaces de estilo de referencia#

    Los enlaces de estilo de referencia son un tipo especial de enlace que hace que las URLs sean más fáciles de mostrar y leer en Markdown. Los enlaces de estilo de referencia se construyen en dos partes: la parte que mantienes alineada con tu texto y la parte que almacenas en otro lugar del archivo para que el texto siga siendo fácil de leer.

    Formato de la primera parte del enlace#

    La primera parte de un enlace de estilo de referencia se formatea con dos conjuntos de corchetes. El primer conjunto de corchetes rodea el texto que debe aparecer enlazado. El segundo conjunto de corchetes muestra una etiqueta que se usa para apuntar al enlace que almacenas en otra parte del documento.

    Aunque no es obligatorio, puedes incluir un espacio entre el primer y el segundo conjunto de corchetes. La etiqueta del segundo conjunto de corchetes no distingue entre mayúsculas y minúsculas y puede incluir letras, números, espacios o puntuación.

    Esto significa que los siguientes formatos de ejemplo son aproximadamente equivalentes para la primera parte del enlace:

    • [hobbit-hole][1]
    • [hobbit-hole][1]

    Formato de la segunda parte del enlace#

    La segunda parte de un enlace de estilo de referencia se formatea con los siguientes atributos:

    1. O rótulo, entre colchetes, seguido imediatamente por dois pontos e pelo menos um espaço (por exemplo, [label]: ).
2. O URL do link, que você pode colocar opcionalmente entre colchetes angulares.
3. O título opcional do link, que você pode colocar entre aspas duplas, aspas simples ou parênteses.

    Esto significa que los siguientes formatos de ejemplo son aproximadamente equivalentes para la segunda parte del enlace:

    * [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle
* [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle "Hobbit lifestyles"
* [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle 'Hobbit lifestyles'
* [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle (Hobbit lifestyles)
* [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle "Hobbit lifestyles"
* [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle 'Hobbit lifestyles'
* [1]: https://en.wikipedia.org/wiki/Hobbit#Lifestyle (Hobbit lifestyles)

    Puedes colocar esta segunda parte del enlace en cualquier lugar de tu documento Markdown. Algunas personas la colocan inmediatamente después del párrafo en el que aparece, mientras que otras la colocan al final del documento (como notas al final o al pie).

    Un ejemplo para juntar las piezas#

    Imagina que añades una URL como un enlace de URL estándar a un párrafo y que queda así en Markdown:

    Num buraco no chão vivia um hobbit. Não é um buraco nojento, sujo e molhado, cheio de pontas
de vermes e com cheiro de lodo, nem um buraco seco, vazio e arenoso, sem nada onde sentar ou onde sentar.
comer: era uma [toca de hobbit](https://en.wikipedia.org/wiki/Hobbit#Lifestyle "Hobbit lifestyles"), e isso significa conforto.

    Aunque pueda apuntar a información adicional interesante, la URL mostrada no aporta mucho al texto sin formato existente y solo lo hace más difícil de leer. Para corregirlo, puedes formatear la URL así:

    Em um buraco no chão vivia um hobbit. Não um buraco nojento, sujo e úmido, cheio de pontas de minhocas e com cheiro de lodo, nem ainda um buraco seco, vazio e arenoso, sem nada onde sentar ou comer: era um [buraco de hobbit](https://en.wikipedia.org/wiki/Hobbit#Lifestyle), e isso significa conforto.

    En ambos casos anteriores, la salida renderizada sería idéntica:

    En un agujero en el suelo vivía un hobbit. No era un agujero asqueroso, sucio y húmedo, lleno de extremidades de gusanos y con olor a lodo, ni tampoco un agujero seco, vacío y arenoso, sin nada donde sentarse o comer: era un agujero de hobbit, y eso significa comodidad.

    y el HTML del enlace sería:

    <a href="https://en.wikipedia.org/wiki/Hobbit#Lifestyle title="Hobbit lifestyles">hobbit-hole</a>

    Prácticas recomendadas de enlaces#

    Las aplicaciones de Markdown no se ponen de acuerdo sobre cómo tratar los espacios en medio de una URL. Por compatibilidad, intenta codificar en URL los espacios con 20%. Como alternativa, si tu aplicación de Markdown admite HTML, puedes usar la etiqueta HTML.

    ✅  Haz esto ❌  No hagas esto
    [link](https://www.example.com/my%20great%20page)

    <a href="https://www.example.com/my great page">link</a>    		 [link](https://www.example.com/my great page)

    Los paréntesis en medio de una URL también pueden ser problemáticos. Por compatibilidad, intenta codificar en URL el paréntesis de apertura (() con %28 y el paréntesis de cierre ( )) con %29. Como alternativa, si tu aplicación de Markdown admite HTML , puedes usar la etiqueta HTML.

    ✅  Haz esto ❌  No hagas esto
    [a novel](https://en.wikipedia.org/wiki/The_Milagro_Beanfield_War_%28novel%29)

    <a href="https://en.wikipedia.org/wiki/The_Milagro_Beanfield_War_(novel)">a novel</a>    		 [a novel](https://en.wikipedia.org/wiki/The_Milagro_Beanfield_War_(novel))

    Escapar caracteres#

    Para mostrar un carácter literal que de otro modo se usaría para formatear texto en un documento Markdown, añade una barra invertida ( \ ) delante del carácter.

    \* Without the backslash, this would be a bullet in an unordered list.

    La salida renderizada queda así:

    • Sin la barra invertida, esto sería un marcador en una lista desordenada.

    Caracteres que puedes escapar#

    Puedes usar una barra invertida para escapar los siguientes caracteres.

    Caracteres Nombre
    \ barra invertida
    ` backtick (véase también escape de backticks en el código)
    * asterisco
    _ guion bajo
    {} llaves
    [] corchetes
    <> corchetes angulares
    () paréntesis
    # almohadilla.
    + signo más
    - signo menos (guion)
    . punto
    ! signo de exclamación

    HTML#

    Muchas aplicaciones de Markdown permiten usar etiquetas HTML en texto formateado con Markdown. Es útil si prefieres ciertas etiquetas HTML a la sintaxis Markdown. Por ejemplo, algunas personas encuentran más fácil usar etiquetas HTML para las imágenes. Usar HTML también es útil cuando necesitas cambiar los atributos de un elemento, como especificar el color del texto o cambiar el ancho de una imagen.

    Para usar HTML, pon las etiquetas en el texto de tu archivo formateado con Markdown.

    This **word** is bold. This <em>word</em> is italic.

    La salida renderizada queda así:

    Esta palabra está en negrita. Esta palabra está en cursiva.

    Prácticas recomendadas de HTML#

    Por motivos de seguridad, no todas las aplicaciones de Markdown admiten HTML en los documentos Markdown. En caso de duda, consulta la documentación de tu aplicación de Markdown. Algunas aplicaciones solo admiten un subconjunto de etiquetas HTML.

    Usa líneas en blanco para separar los elementos HTML de nivel de bloque, como , <div> y del contenido circundante. Intenta no sangrar las etiquetas con tabulaciones ni espacios — esto puede interferir en el formato.<table><pre><p>

    No puedes usar la sintaxis Markdown dentro de etiquetas HTML de nivel de bloque. Por ejemplo, <p>italic and **bold**</p> no funcionará. F
